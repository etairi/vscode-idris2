## Decisions

- **Always bracket** (user, 2026-10-01; ROADMAP §9). An answer put in place of a hole that is more
  than one token goes in parentheses wherever the hole is: Intro (also a single candidate applied
  without asking), Refine Hole… and its ambiguity alternatives, Proof Search and its next results,
  Make Lemma's call. Make Case always applies the bracketed case. Why: the analysis that left the
  parentheses out where a hole "stood alone" (rounds 9–15) missed a case in every round, each a silent
  change of the user's program; it is deleted. How it is built: *Edits*.
- **Keep the layout refusal and make it converge** (user, 2026-10-01; ROADMAP §9). A wider text in
  place of the hole moves the rest of its line; when that rest starts a layout block continued below,
  the program can change silently: `f x = 2 * case x of _ => 2` / `+ 3` (22 spaces) gives `f 0 =
  10`, the same with `(S 1)` for the first `2` gives `f 0 = 7`, and both check [live, idris2 0.8.0,
  each `f 0` by `Refl`, rechecked by the docs lane of the convergence pass with `idris2 --check`,
  `/tmp/vi2-m4/docs-cv/live/LA.idr`, `LB.idr`]. The refusal stays
  (*Blocks after the hole*); the line reader now shares M0's lexer (*The line reader*). After the
  pass one final review: only a high finding or a regression of the pass is fixed; medium and low
  findings go to *Open issues*.
- **Q25** (user, 2026-10-01): the keybinding letters stay the Idris docs' Vim ones. **Q26** (user,
  2026-10-01): Next Result (`n`) continues the document's cycle of either kind (*Edits*, *Searches*).
- **Q24** (user, 2026-09-30): Refine Hole… may run the elaborator scripts its expression reaches, as
  Evaluate may (Q23); documented, not refused (*Security*).

## Deviations from ROADMAP §5 M4

1. **Case Split on `f n = n`** (`Plain.idr`) is refused before anything is sent — "this line has no
   hole to split on. The compiler rewrites the cursor's line only, so the clause must be on it, its
   right-hand side a hole ?name." — not rephrased from the compiler's answer: the compiler answers
   line L alone, rewritten (*Edits*), so the backend asks only when line L holds a `?hole` token. `No
   clause to split here` still arrives, and is rephrased, on a line that holds a hole under something
   else (a `let`, `S ?h`).
2. **F16 does not hold** for Case Split, Add Clause and Generate Definition (ROADMAP F16
   correction): after a load that returned an error they are refused unsent ("the file did not load
   cleanly — fix the first error and save"). The other kinds are sent; their failures after such a
   load show that advice first and the compiler's text after it.
3. **Add Missing Cases** inserts after the function's clauses (`clausesEnd`: the one run of entries
   of the declaration's layout block that are its clauses, also later than the declaration, as in a
   `mutual` block; two runs are refused), not at the first blank line after the declaration
   (idris2-lsp's convention, which lands inside a `where` block that has a blank line). On
   `Part.idr` both give the acceptance's place. From the Command Palette it also acts on a type
   declaration without a coverage error, so that a `partial` function can be completed.
4. **Make Lemma** puts the type (and a blank line) above the type declaration of the function the
   hole's top-level clause defines (`clauseName`: also an infix operator, an operator in prefix form
   or a backticked name), with the doc comments, comments and modifier and pragma lines right above
   it; in a `namespace` or `mutual` block above the enclosing declaration in that block, indented as
   it. The compiler's REPL and idris2-lsp use the nearest blank line above the hole (`addMadeLemma`
   [src]), which can be inside a `where` block or between two clauses. Refused in an `interface` and
   in the fenced literate styles; not applied when the call passes a name the compiler made
   (`conArg`, `lcase`).
5. **The edit contract** refines ARCHITECTURE §3.3 (`EditRequest` by kind with `version` and
   `token`; `EditResult` = `edit` | `choices` | `failed` | `exhausted`): ARCHITECTURE §3.3 *As built
   (M4)*.
6. **Cancel.** A cancel before the request is written drops it; after, it restarts the root's
   `check` session only (`SessionPool.restartCheck`).
7. **Next / Previous Hole** move through the `?name` tokens of the text the editor shows (M0's
   lexer), not through the compiler's locations, which describe the file as last loaded and need a
   trusted workspace and a running compiler.
8. **The light bulb** is narrower than ARCHITECTURE §10's syntactic rule: Case Split only on a
   variable not starting with a capital of a one-line clause whose right-hand side is a bare hole and
   that has no `where` block below; Add Clause and Generate Definition only on a declaration no clause
   of the name follows, not `%foreign` or `%extern`; most actions the backend refuses unsent for their
   line are left out or shown disabled with the reason. Some refusals show only when the command
   runs: a lone `\r` in a file that is not literate, a file that ends inside a block comment or
   string, Make With on a NUL in the left-hand side, and those that depend on the lines below or the
   rest of the definition (the actions at a hole but Make With when the rest of its line opens a
   block that the next code line is read against or the hole is in a `parameters`/`using`/`with` header, Make Lemma on a hole named like a local, Make With when `?<h>_rhs` exists, Add Missing Cases on clauses in two places). A code
   action's argument is honoured only while the name at its position is still the one offered. No
   code action carries `refactor.rewrite.GenerateDefNext`: Next Definition is a command, `g` on the
   declaration or its result, `n`, and the status-bar item.
9. **Fixtures.** The acceptance's `literate/Lit2.lidr` is `broken/Lit2.lidr`, so that one loose
   workspace holds every editing fixture.
10. **E23** was checked as in M3 (VS Code's resolved Default Keybindings in the `intelligence-loose`
    suite), not against a checked-in snapshot.
11. `idris2.holes.showInSideBar` only hides the view; the model still asks after every load
    (*Open issues*).
12. **Cycles** end on any change of their document (an undo, a change inside the result), not only
    on an edit outside the result (ARCHITECTURE §10), and hold the document's save checks while they
    run.
13. **No text inserted for review.** ROADMAP §5 M4 *Risks* plans, for wrong line replacements, to
    insert the text and select it for review. Not built: where the compiler's answer would be wrong,
    the command refuses before sending, or does not apply the answer, and says why.

## Edits

- **Requests** (`backend/ide/edits.ts`). Every kind is one request, built through the s-expression
  encoder; lines and columns come from `core/positions.ts` (`toIdeCaseSplitRequest`,
  `toIdeLineRequest`, and `toIdeSourceLineRequest` for the three kinds that read the raw source line,
  *Literate files*). Proof Search sends the plain form (F31) and an operator hint bare, as the
  compiler names operators (`UN (Basic h)` [src `IDEMode/REPL.idr` 185]).
- **Where the answers go (E15)** [live, transcripts `clean-editing`, `edits-shapes`,
  `edits-searches`, `edits-names`, `lit2-editing`; src as cited in `edits.ts`, whose module comment
  is the full rule set]:
  - Case Split replaces line L; asked only when line L holds a hole token (a `?` that starts a token,
    after `[<` or `[|` too), never on an as-pattern's name, which the compiler does not rewrite
    (`namesAsPattern`); an answer that only repeats the clause is not applied.
  - Add Clause and Generate Definition insert after the declaration's last line (its `f :` line and
    the more indented lines after it; idris2-lsp's `endLine loc + 1` [src]); Add Clause after the
    function's clauses when it has some. Both answer for any line of the declaration and ignore the
    name except in messages; on `a, b : …` they answer for `b` [live, `edits-layout`], so a
    declaration of several names is refused. A signature whose `:` starts the next line is read over
    its lines (`entryCode`).
  - **Parentheses** (decision of 2026-10-01). Intro (every candidate, a single one included), Refine
    and its ambiguity alternatives, Proof Search and its next results, and Make Lemma's call replace
    the `?h` token through `inPlace`: as printed when the answer is one token (`core/idrisSyntax.ts`
    `isOneToken`: a name, qualified or not, a number, a string or character literal, a hole, an
    operator in parentheses, or one bracket group spanning the whole answer whose brackets match —
    not `(a) + (b)`, not `(a]`), else in parentheses. A postfix projection `.x` counts as more than
    one token: the lexer reads one (`dotIdent`), but the parser applies it to the expression before
    it, space or not (`simpleExpr`, `Idris/Parser.idr` 572–581 [src]); with `(.x) f = f . f`, `h =
    three .x S 0` checks as `h = 9` and `h = three (.x) S 0` as `h = 8`, and with a record field
    `x`, `h = g .x` and `h = g.x` fail where `g (.x)` and `g(.x)` check [live, idris2 0.8.0, final
    review of the convergence pass, `/tmp/vi2-m4/rv-reg-cv/live/S2.idr`, `S3.idr`, `P2.idr`,
    `P3.idr`, `/tmp/vi2-m4/fix-cv/G1.idr`, `G2.idr`]. A token goes in parentheses too where it would
    join the text next to it: one that starts with a name's character right after one (`g?h`, which
    the lexer reads as `g ?h`), one that ends with one right before a `.` (*Facts found*, *Next to a
    hole*), and a string literal right after or before a `"`: a string ends at a `"` not followed by
    another (`Parser/Lexer/Source.idr` 336 [src]; `g "a""x"` fails with `Bracket is not properly
    closed` [live, second review of the fixes]). After a backtick a space goes before an answer that
    starts with `(`, `[` or `{`, which would open a quotation (``x `div`(id 1)`` fails with `Not the
    end of a block entry`, ``x `div` (id 1)`` loads [live, convergence pass]). At the head of an
    idiom bracket on the hole's line (`[|`, then only white space and `(`) only a name, a hole or a
    lambda is put, anything else refused (`idiomHeadProblem`): the compiler drops the parentheses
    and reads an application there as applicative (`Idris/Desugar.idr` 279–291, 417, 526–531;
    an integer literal is `fromInteger x`, 443–451 [src]); `[| (S ?h_0) |]` loads with `?h_0 :
    Maybe Nat` [live, third review of the fixes], `[| 0 |]` does not check [live, convergence
    pass]. An answer without a token is refused. The compiler brackets only a prefix
    application's argument (`bracketholes`, set in `argExpr` only, `Idris/Parser.idr` 263 [src]):
    next to an operator a lambda takes the rest of the expression in (`\arg => ?f_0 <$> xs`) and an
    operator application re-associates (`?h_0 + ?h_1 * 2`) [live, ninth round]. QuickPick labels stay
    as the compiler printed them; a candidate the compiler bracketed itself (`(S ?h_0)` for a prefix
    argument) is one token and goes in as it is.
  - **Make Case** replaces the hole's line, asked only when the first `?h` text of the line is the
    hole at the cursor. `makeCase` (`Idris/IDEMode/MakeClause.idr` 57–81 [src]) replaces that `?h` by
    `case _ of` and puts, on a new line indented by the number of characters before the hole plus 5,
    `case_val => ?h` followed by the rest of the line; for a prefix argument it brackets the two,
    `(case _ of` … `case_val => ?h)`, indent plus 6. Unbracketed, the case takes in the rest of the
    line and the lines below indented past `case_val`. `madeCase` builds both forms from the line:
    the bracketed answer is applied as it is, the unbracketed one is rewritten into the bracketed
    form, anything else is refused ("the compiler's answer has an unexpected form; nothing was
    applied"). A hole already in parentheses gets two pairs (`((case _ of` … `?h)) * 2`).
  - **Blocks after the hole** (`layoutProblem`). Make Case moves the rest of the hole's line 19
    columns to the right, and an answer in place of another width than `?h` moves it too. When that
    rest starts an entry of a layout block (`core/idrisSyntax.ts` `opensBlockOnLine`, inside brackets
    and string interpolations too), or the code of the hole's entry before it, from the line
    `edits.ts` `entryStart` takes as its first (*The header*), ends inside a `parameters`, `using` or `with` header, whose block's first entry can follow on the line
    (`holdsBlockHeader`), that entry's column moves, and the lines below are read against the new
    column: `f 0` 10 → 7 (*Decisions*); on `f x = ?h * case x of _ => 1` / `+ 2` in column 23,
    `f 0 = 30` with `10` for the hole, 12 after Make Case's text or Intro's `(S ?h_0)`; an aligned
    next entry of a `where` or a `\case` after the hole stops parsing [live, *Facts found*]. So Make
    Case, Intro, Refine, Proof Search and Make Lemma are refused before sending unless the first token
    below is at the hole's column or left of it, or there is none (`nextTokenColumn`: the column the
    compiler's layout reads, past white space, U+00A0 included, and block comments, also one that
    starts above): such a token ends every entry the rest starts, in either text (not the entry of
    an enclosing block begun on a line above, nor an entry whose first token is a bracket still
    open at the line's end: *Open issues*). A line below that starts in a `"""` string's text refuses. A next result replaces a result that passed this check.
    - *The openers* are every block call of `src/Idris/Parser.idr` 0.8.0 (the family `block`,
      `blockAfter`, `blockWithOptHeaderAfter`, `nonEmptyBlock` and `nonEmptyBlockAfter` of
      `Parser/Rule/Source.idr` 618–691 [src]), listed with their line numbers in the comment above
      `ENTRY_KEYWORDS` in `core/idrisSyntax.ts`, each tested in `test/unit/idrisSyntax.test.ts`:
      `where` (clause, `data`, interface, implementation, record), `of`, `do`, `M.do`, `let`,
      `\case`, `` `[ ``, `%foreign`, `%export`, `%nomangle`, `%foreign_impl` with its name, `mutual`,
      `failing`, `namespace` with its name, `using`, `parameters` and `with` after their headers, `|`
      (`patAlt`) and `;` (`terminator`). Read conservatively: any `|` (a list comprehension's too,
      not that of `|]`, except on a line that starts inside brackets opened above: *Open issues*), a `where`'s options or constructor name as its first entry, a block that
      also closes on its line. The module's own blocks (`progHdr`, `prog`) never start after a hole;
      an interpolation is not a block (`interpBlock` 1073).
    - *The header* (`holdsBlockHeader`) is true only when, after the keyword, only that header's
      tokens come and the code ends inside one of its brackets. `layoutProblem` passes it the hole's
      entry from what it takes as its first line: the nearest line above, not continued, whose first token is left of
      the hole line's (`entryStart`; it may take in earlier entries of a block, which end the header
      reading; a header with a line between that starts left of the hole's is missed: *Open issues*). So `parameters (n : Nat)` / `(m : ?h) g : Nat`, the old comma syntax and `using (x : Nat,` /
      `y : ?h) g : Nat`, each with an aligned `g = 1`, are refused (unit, `edits`; `(Maybe Nat)` in the
      hole's place gives `Expected end of input` [live, third review of the fixes]).
  - **The line reader** (`core/idrisSyntax.ts`: `scanned`, `levelTokens`, `openAfter`,
    `firstTokenColumn`, `opensBlockOnLine`, `holdsBlockHeader`, `isOneToken`, `caseSplitLineProblem`)
    reads no lexeme itself since the convergence pass: it runs `core/idrisLexer.ts` `lexText`, M0's
    lexer, a line at a time (`'line'` mode), and M0's `lex()` runs it on whole texts (`'text'` mode);
    `lex()`'s tokens and groups are unchanged (*Convergence pass*). Carried over a line break, as
    the compiler's lexer does (`Parser/Lexer/Common.idr`, `Source.idr` [src]): a block comment (its
    depth, a string open in it), a `"""` string, a `"` string whose escape `\` (with its `#`s) ends
    the line (the escape takes the break), an interpolation's code and the brackets open in code, and
    a character literal whose `'` or `'\` ends the line. Any other `"` string open at a break ends
    there, unclosed, as in `lex()`, and the reading is `unsure` from then on (the compiler rejects
    such a file); `opensBlockOnLine` then answers that a block opens. Read line by line, a text that
    ends with a line break gets what `lex()` reads on the whole text but for three cases (the module
    comment of `core/idrisLexer.ts`; pinned in `syntaxLexer.test.ts`, *a line at a time*): a `\r`
    before a break is not seen (CRLF), a `%cg` directive is read within its line (none in any
    corpus), and a character literal cut by a break that the next line does not close is taken for
    one (code the compiler rejects). A last line without a break is read as if one followed. `isOpen`
    (`EditText.continued`, `declaredModule`) is true inside a block comment, a string's text, an
    interpolation's code and after a cut character literal; brackets do not count. A string literal
    of any form is a token of its own kind, so Case Split's string check covers raw strings (`f xs
    #"xs"# = ?f_rhs` refused). Token bounds now follow the compiler's lexer: `x.field` is two tokens
    and `12abc` too, so such answers get parentheses; `a.do` is not a namespaced `do`; `?a.b` holds
    the hole `?a`. What is open is a stack the lines share, so a line costs its own length (40,000
    lines each opening a string inside the last one's interpolation: under 200 ms,
    `holesView.test.ts`).
  - **Layout columns** (convergence pass). `edits.ts` reads every line's layout column from its first
    token (`entryAt` through `firstTokenColumn`: code points, past white space, U+00A0, `\f`, `\v`
    and block comments) in all its readers of an entry's extent (`entryEnd`, `siblingLines`,
    `enclosing`, `declarationAt`, `clausesEnd`, `lemmaPlace`, `isLocal`, `inParameters`,
    `qualifiedName`), and new lines get that column, every character before the first token but a
    tab written as a space (`layoutIndentation`). Before, Add Missing Cases on `g 0 = 1` /
    `{- c -}  + 2` put the new clause between the two lines, and the file still loaded, with
    `g 0 = 1` instead of 3 [live, convergence pass, `LC.idr`, `LC2.idr` in
    `/tmp/vi2-m4/edits-cv/live/`].
  - Make With replaces the clause's lines up to the hole's, only when, up to the end of the hole's
    line, the right-hand side is the hole alone after the first `=` the compiler's `readLHS` finds
    and the text before it is a function clause's left-hand side (`withClauseStart`; a clause that
    goes on below is not refused, and those lines stay below the new nested clause: *Open issues*); `=>`, a `let` binding, a one-line `where` and an application are

  - A `-Next` replaces the previous result's range (a Proof Search result with the parentheses added
    to it), keeping its leading or trailing line break; a next proof search result is bracketed by
    the same rule (a next definition is not).
  - Refine's ambiguity alternatives (F29) are offered only for an expression of one name, when each
    alternative is that name, qualified, followed by its arguments (`isNameApplied`), and applied as
    printed, qualified (refining with a qualified name answers with the qualification dropped,
    ambiguous again [live, `ambig-holes`]; `A.(+++)` answers `?g_rhs_0 +++ ?g_rhs_1` [live,
    convergence pass]). For a binary operator with a fixity the compiler prints each alternative
    infix, `?g_rhs_0 AmbOp.A.(+++) ?g_rhs_1`, which as source applies the hole to two arguments and
    still loads [live, third review of the fixes; rechecked in the convergence pass]: refused, with

## Open issues

- **Stop Backend right after two saves** (M2's checks; *Packaged-extension check*): with a load in
  flight from the first save, Stop Backend stopped the session, and it was started again at once with
  a new load of the file [live]. Most likely the second save's check, waiting behind the first, ran
  once the stop ended that load (a guess, not traced); the guide's "the next check starts it again"
  covers it only if that check counts as the next one. Not changed in M4.
- **Known limitations of the edits after the convergence pass** (low; recorded, not fixed):
  - The idiom-head refusal sees only a `[|` on the hole's line with only white space and `(`
    between it and the hole; Intro is refused as a whole there when any candidate is not a name, a
    hole or a lambda; an operator in parentheses there (`(+)`) is refused although it is a name.
  - A hole right after a raw string's closing `"#` (`f = g #"x"#?h`, which loads [live]) is not
    found: `edits.ts` `startsToken` reads `#?` as an operator, a small reader outside the shared
    lexer. A false refusal.
  - Refine's alternatives in the backticked infix form (``?h_0 `M.A.foo` ?h_1``) are refused,
    although they would be right.
  - A line that starts inside a block comment opened on an earlier line belongs to the entry of the
    line that opened the comment (`EditText.continued`), whatever token follows the comment's end;
    `nextTokenColumn` (the block refusal, Case Split) does read that token's column.
  - Over-refusals of `opensBlockOnLine`, only when the first token below is right of the hole: any
    `|`, a `where`'s options or constructor name, a block that also closes on its line.
  - Answers `x.field` and `12abc` now get parentheses (two tokens to the compiler's lexer too).
  - `unsure` (a `"` string a line break ends) makes only `opensBlockOnLine` conservative; the other
    readers take the lines below as code, as `lex()` does. It arises
    only in a file the compiler's lexer rejects, or where `lex()` itself is wrong (the oracle found no
    such case).
