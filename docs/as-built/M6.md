## Decisions

Taken by the author while building, within ROADMAP M6 and ARCHITECTURE §6.3; the first one departs
from an acceptance item, and the user kept it for now (2026-10-24, ROADMAP §9).

1. **A package file in the shadow directory** (E9; *Deviations*). The plan gave the `shadow` session
   `-p <dep>` for each `depends` entry and the `.ipkg`'s `opts` on its command line, in a directory
   with no `.ipkg` above it. Two findings changed that. `-p p` adds that one package and none of its
   dependencies (`addPkgDir p anyBounds`, `src/Idris/SetOptions.idr` 188–193, 436–438 on v0.8.0
   [src]): a module importing `Test.Golden` failed with `Error: Module System.Path not found` under
   `-p test` (`test` depends on `contrib`) [live, 2026-10-24]; and the compiler applies an `.ipkg`'s
   `depends` with their bounds and their own dependencies, and its `opts` as `preOptions`, at every
   `:load-file` (`findIpkg` → `addDeps`, `processOptions`, `src/Idris/Package.idr` 392–467,
   1093–1109; every IDE-mode `:load-file` calls `findIpkg`, `src/Idris/IDEMode/REPL.idr` 145–149
   [src]), while on a command line some options act otherwise. So the shadow directory holds
   `shadow.ipkg`: the root's package name, `sourcedir = "src"`, its `depends` with their bounds as
   written, and its `opts` but the options that name the compiler's directories or written files
   (`src/backend/ide/shadow.ts` `shadowPackage`); the compiler then gives the copy the root's packages
   and options exactly as it gives them to the `check` session. With a `shadow.ipkg` of `depends =
   test` the same module loaded (`(:return (:ok ()) 1)`) [live]. The package file also ends the
   compiler's walk for an `.ipkg` in the shadow directory, so that no `.ipkg` above the extension's
   storage can be applied, and with `sourcedir = "src"` a load applies it over a `--source-dir` of
   `idris2.ideMode.extraArgs`. Loose files get one too (`package shadow`, no `depends`).
2. **The options left out of the package file** are `--build-dir`, `--source-dir`, `--output-dir`
   and the four `--dump…` options, with the word each takes (they would move the copy's build or
   source directory, or write where the user's build writes); every other option acts as for the
   `check` session. The words are read with a model of the compiler's option parser only when one of
   these occurs (`OPTION_WORDS`, the 77 flags of `options`, `src/Idris/CommandLine.idr` 234–394, with
   the word rules of `processArgs`, 453–487 [src]; the table was compared with the source flag by flag,
   identical); a `--source-dir` there is the source directory the copy's path is computed from. Words
   the parser model cannot read around such an option (an unknown `--x`, an option without its word),
   a control character in a word, a bound that is no version, or an unreadable package file mean no
   check of unsaved text for the root (the saved file's results stay; the reason is logged).
3. **A window's own storage**: `<globalStorage>/shadow/<process id of the extension host>/<16 hex
   digits of a hash of the root>/` (`features/shadow/register.ts`). VS Code gives every window of a
   profile one global storage, so two windows of one project would otherwise write one copy. At
   activation the directories of extension hosts that no longer run are deleted (`process.kill(pid,
   0)` failing with `ESRCH`); at deactivation, at once (`fs.rmSync`: VS Code ends the extension host
   right after `deactivate()`, before an asynchronous removal finished — the first packaged-extension
   check found the folder left), and when `idris2.checkOnType.enabled` changes, the window's own.
4. **Only the copy of the document checked last** lies in `src/`: a copy of another document empties
   `src/` and `build/` first. The compiler looks for an import in its own build directory before the
   search path (`nsToPath`, `src/Core/Directory.idr` 198–207 [src]), so a module built there from
   another document's unsaved text would hide the `check` session's build of it.
5. **After Stop Backend, a give-up or a refusal of the root's folder, nothing is checked while
   typing** until a check (a save, Check File) starts the compiler again — the rule of M3's passive
   queries (`features/intelligence/types.ts` `DocumentQueries`): typing does not undo Stop Backend.
6. **Queries and edits of a document with unsaved changes go to the `shadow` session while its last
   check read exactly the lines the document shows** (`IdrisBackend.showsUnsavedCheck`): `typeAt`
   (its answer marked `TypeInfo.unsaved`, which the hover shows without the stale note), `docsFor`,
   `holes`, `edit` and the `-Next` of a search started there. Otherwise the `check` session answers as
   in M3/M4. `definition`, `completions` and `browseNamespace` stay on the `check` session.
7. **The editing commands save nothing** while `showsUnsavedCheck` holds: the compiler edits the text
   the document shows (`features/editing/commands.ts`).
8. **The status item** gives the unsaved check's counts while its diagnostics are shown ("checked
   the unsaved text: …; a save checks the file"; `CheckStatus.unsaved`); a check that could not run
   leaves the saved file's status and diagnostics, and its reason goes to the log at `info`, once per
   reason and document.
9. **A module not built yet** (`Module X not found` for a file of the root's source directory):
   each such file is checked as saved once per document while it has unsaved changes, through
   `DocumentChecks.check` (so its diagnostics are shown), and the text is checked again; what that
   check reports is shown, also when the module is still missing (its file has errors, so its check
   wrote no build files).
10. **Test profiles turn check while typing off** (`.vscode-test.mjs` `BASE_SETTINGS`): a test that
    edits a document without saving would otherwise start a `shadow` session — with the fake compiler,
    requests no recording has; in the e2e suite a second real compiler (CLAUDE.md: one at a time). The
    M6 suites turn it on and restore it.
11. **No check of a document that an automatic save saves soon** (asked for by the user on 2026-10-24,
    after the commit; `unsavedChecks.ts` `savedSoon`). Otherwise every pause in typing compiles the
    text twice, the check of the unsaved text after 500 ms and the save's check after it. The rule:
    the save is checked (the trigger is not `manual`), and VS Code saves the file after a short delay,
    or `idris2.checking.trigger` `afterDelay` saves it within 1000 ms. VS Code's own test is used for
    the first: `isShortAutoSaveDelay` holds when `files.autoSave` is `afterDelay` with a
    `files.autoSaveDelay` of at most 1000 ms (`DEFAULT_AUTO_SAVE_DELAY`), `files.autoSaveWhenNoErrors`
    is off, and `files.autoSaveWorkspaceFilesOnly` is off or the file is inside a workspace folder
    (`FilesConfigurationService.computeAutoSaveConfiguration`; a delay that is not a number of at
    least 0 reads as 1000, `core/config.ts` `readAutoSaveSettings`) [src: the workbench bundle of VS
    Code 1.143.1]. VS Code treats that delay as short itself (`AutoSaveMode.AFTER_SHORT_DELAY`) [src];
    with a longer one the check of the unsaved text answers earlier, so it stays. The settings are read
    with the document as the scope, so a language's own values apply; the rule is read at each edit
    and when the delay ends. Tests: `unsavedChecks.test.ts` (*savedSoon*, *a document an automatic
    save saves soon*), `config.test.ts` (*VS Code's auto-save settings*), and the e2e test *VS Code
    saving after a short delay*, which shows VS Code saving the file within its delay [live].

## Deviations from ROADMAP §5 M6

- **Acceptance "the shadow directory contains no `.ipkg`"**: it contains `shadow.ipkg`, which the
  extension writes (*Decisions* 1). The item's intent — the compiler never finds the project's own
  `.ipkg` and never builds the user's files (F13) — holds: the e2e test asserts the one `.ipkg` is
  `<shadow directory>/shadow.ipkg` and the build directory of the `check` session unchanged.
- **"args … `-p <dep>` for each `depends` entry plus the ipkg `opts`"**: through the package file
  instead (*Decisions* 1, 2); `-p` only for `idris2.ideMode.loosePackages`, as for a loose file's
  `check` session.
- **"`((:load-file "<rel path>") id)`"**: the copy's absolute path below the real path of the shadow
  directory, as every load of the extension (M2, *The path in `:load-file`*).
- **"still failing → saved-only for this document with a status hint"**: the retry's own answer is
  shown (*Decisions* 9); a check that cannot run at all falls back to the saved file's results with a
  line in the log (*Decisions* 8).
- **"the shadow directory is cleaned on deactivate"**: and when the setting changes, and the
  directories of ended windows at activation (*Decisions* 3).
- **"Only the active editor's document is shadowed"**: as planned; a document's unsaved diagnostics
  stay while another editor is active, until it changes, is saved or closed.

## The shadow session

`src/backend/ide/shadow.ts` (the package file, the copy's path, the directory's name) and the pool
(`pool.ts`): the `shadow` role of `types.ts` `SessionRole`.

- **Command line**: the transport flag, `--no-color`, `-p` for each of `idris2.ideMode.loosePackages`
  (loose roots), `idris2.ideMode.extraArgs`, `--build-dir <shadow directory>/build` last; working
  directory the shadow directory; `IDRIS2_PATH` = `effectiveCheckBuildDir(root)/ttc`, before any
  `IDRIS2_PATH` of `idris2.toolchain.env` or the extension host. No `realCwd`: the extension owns the
  directory.
- **Consent**: the gate judges the root's own directory (`ProjectIndex.sessionCwd`), not the shadow
  directory: what the session compiles is the project's code.
- **First request** (`session.ts`, *First request*): `(:enable-syntax :False)` (F14) to every new
  process, right after the handshake, before any request that waits; the session is not idle until it
  is answered.
- Like the `eval` session it never starts a process by itself (an unexpected end leaves it `stopped`),
  is stopped instead of restarted (Restart Backend, a changed command line, a package file that can no
  longer be written), stops after `EVAL_IDLE_TIMEOUT_MS` (2 min) without a request, counts towards
  `idris2.ideMode.maxSessions` while idle and is evicted first; it drops `:highlight-source` frames of
  the request in flight unread. `SessionPool.stopShadows` stops shadow sessions only;
  `restartShadow` restarts a busy one (cancellation).

## Unsaved text in the backend

`IdeBackend.checkUnsaved` (`backend.ts`): the copy and the package file are written right before the
`:load-file` is written (`beforeSend`, when nothing is in flight), so the copy holds exactly the text
loaded; merged checks of one document send the newest text. The load's diagnostics are converted with
that text (bird tracks, code points) and given to the document, source `idris2 (unsaved)`, related
places in the copy moved to the document; a package-file error is a `problem`. The load is announced
(`LoadedDocument.unsaved`, `rebuilt` false): `StaleAnswers` drops only that file's answers, and the
holes model replaces only that file's holes, located in the copy only (the imports' holes keep what
their own loads gave). `unsavedTextChanged` restarts the root's shadow session when its check has been
answering for more than `SHADOW_RESTART_AFTER_MS` (2 s) when a newer text arrives.

## Check while typing

`features/shadow/unsavedChecks.ts`: the active editor's Idris document with unsaved changes, checked
`idris2.checkOnType.delay` (500 ms) after the last change; a newer change cancels the check that waits
and tells the backend; a save, an undo back to the saved text, a revert or a close removes the entry
and shows the saved file's diagnostics again; M4's cycling holds pause it. `DocumentChecks` keeps its
own entries and counts while a document's are hidden (`ShownDiagnostics`).

## Facts found

- [src] v0.8.0: every IDE-mode `:load-file` calls `findIpkg`, which walks up from the current
  directory to the first directory with any `.ipkg` and applies `builddir`, `outputdir`, `opts`
  (`preOptions`) and `depends` (`addDeps`: transitive, with bounds and backtracking, data
  directories) (*Decisions* 1).
- [src + live] `-p` adds one package without its dependencies (*Decisions* 1; scratch E9b).
- [src] The option parser's word rules (*Decisions* 2); an unknown word not starting with `--` is an
  input file, which `preOptions` ignores.
- [src] The ipkg lexer keeps a string literal's text raw (`StringLit (stripQuotes s)`,
  `src/Parser/Lexer/Package.idr` 115): the package file writes the `opts` words back as they are.
- [src] `isTTCOutdated` rebuilds a module whose source is at least as new as its TTC
  (`src/Idris/ProcessIdr.idr` 252–262): a copy written before each load is always rebuilt.
- [live, recordings `shadow-type-error`, `shadow-hole`, 2026-10-24] In a shadow directory with
  `IDRIS2_PATH` naming a check build's TTCs: `(:enable-syntax :False)` → `(:ok "Syntax highlight
  option changed to False")`; the copy's load builds `Foo.B` only (`1/1: Building Foo.B (…)`), finds
  `Foo.A` in the TTCs, sends no `:highlight-source`, names the copy `src/Foo/B.idr` in its
  `:warning`; `:name-at "arg"` locates the hole in the copy; the session writes only into its own
  `build/`.
- [live, VS Code 1.143.1] `DiagnosticCollection.get` returns `[]`, not `undefined`, for a URI deleted
  from the collection.

## Limitations

- **Unsaved siblings**: a module the document imports is read from its last build (the `check`
  session's), not from its unsaved text (ROADMAP M6, *Scope*).
- **New names** typed and not saved have no semantic token, so the hover finds no occurrence there;
  Go to Definition, completion and the namespace browser answer from the saved file.
- **idris2-lsp roots** are not checked while typing (U1.5/U3).
- **A file outside its package's source directory** is not checked while typing (the compiler would
  not check it as a module of the package either).
- **A package with a `builddir`** gives the shadow session the TTCs in that directory, the user's own
  builds' (D5; may be older than the saved files).
- The copy is written as UTF-8; a file kept in another encoding is checked in UTF-8.
- Two processes per root while typing (the `check` and the `shadow` session), as with M3's `eval`
  session; `idris2.ideMode.maxSessions` evicts the idle shadow session first.
- **Auto-save that VS Code turns off by itself** for a file (`autoSaveDisabledOverrides` in
  `FilesConfigurationService` [src], which no API shows) is not seen (*Decisions* 11): such a file
  under a short `files.autoSaveDelay` is not checked while typing, and is checked when it is saved.
