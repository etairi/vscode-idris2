# M0 manual checklist

This is the "Manual" test layer of `docs/ARCHITECTURE.md` §12 for milestone M0 (`docs/ROADMAP.md`
§5). Work through it on the packaged extension before tagging M0. It checks what the automated
suites cannot see: the installed `.vsix`, what the editor shows, and the logs.

**Setup.** Use a throwaway profile with a short path: the Electron IPC socket path must stay
below the Unix limit (F17), so keep `--user-data-dir` under 60 characters. Pass
`--shared-data-dir` as well: VS Code 1.139 otherwise opens `~/.vscode-shared/sharedStorage`
even with a separate user-data-dir, which also carries your trusted-folder list into the test
profile. On macOS the CLI is
`"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code"`; `code` below stands
for it.

```sh
npm run package                                    # → vscode-idris2-<version>.vsix
V=(--user-data-dir /tmp/vi2-m0/u --extensions-dir /tmp/vi2-m0/e --shared-data-dir /tmp/vi2-m0/s --disable-telemetry)
code "${V[@]}" --install-extension vscode-idris2-*.vsix
code "${V[@]}" test/fixtures
```

`V` is an array so that the flags stay separate words in both bash and zsh (zsh does not split
an unquoted `$V` string). `--disable-telemetry` keeps the fresh profile from sending VS Code's
usage telemetry, which would name the unpublished extension (the flag is not in `code --help`,
but VS Code 1.139.1 accepts it: `cli.js` declares it, and the workbench treats telemetry as off
when it is set [src]). Nothing in this checklist needs telemetry.

1. **Installs and activates cleanly.** Run `code "${V[@]}" --list-extensions --show-versions`:
   it lists `etairi.vscode-idris2`. Then open `workspaces/loose-file/Hello.idr`.
   - The status bar shows the language mode **Idris 2**.
   - **Developer: Show Running Extensions** lists the extension with an activation time below
     100 ms. This is the metric of the M0 acceptance: VS Code 1.139.1 shows
     `codeLoadingTime + activateCallTime` there. Record the figure for the first launch in the
     fresh profile and for a relaunch in `docs/as-built/M0.md`, *Activation time*. The same two
     numbers are in `/tmp/vi2-m0/u/logs/<session>/telemetry.log` (event
     `extensionActivationTimes`) when VS Code is started with `--log trace`, but only while
     telemetry is enabled, i.e. without `--disable-telemetry`, which in a fresh profile means VS Code also sends its usage
     telemetry; the view needs neither.
   - The Extension Host log (**Developer: Show Logs…** → Extension Host) has no error or warning
     that mentions `vscode-idris2`, `idris2`, a grammar, a snippet file or a language
     configuration.
2. **All three languages are recognised.** `grammar/BirdTracks.lidr` opens as **Literate
   Idris**, with its code lines highlighted as Idris and its prose left plain.
   `grammar/Handwritten.ipkg` opens as **Idris 2 Package**, with its field names highlighted.
3. **Scopes are right.** In an untitled `idris2` file (**Change Language Mode** → Idris 2),
   type `failing`, `\case`, `?hole`, `%default total`, `0 x : Nat`, `"a \{x} b"`, `"""`,
   `#"raw"#`, `||| doc` and `{- {- nested -} -}`. **Developer: Inspect Editor Tokens and Scopes**
   should give each one the scope the grammar snapshots expect: for example,
   `variable.other.hole` on `?hole`, and `keyword.*` on `failing`. `class`, `instance`,
   `codata`, `dsl` and `syntax` are **not** coloured as keywords.
4. **Editor behaviour.**
   - **Toggle Line Comment** inserts `-- `, and **Toggle Block Comment** wraps the selection in
     `{- -}`.
   - Brackets `()`, `[]` and `{}` pair and match.
   - Indentation folding works on a `where` block.
   - Double-clicking `hole` in `?hole` selects `?hole`, and double-clicking `x'` selects `x'`
     (the `editor.wordSeparators` default).
   - Pressing Enter after a line ending in `where`, `do` or `of` indents the next line.
   - In `grammar/BirdTracks.lidr`, pressing Enter at the end of a `> ` code line starts the new
     line with `> `; at the end of a prose line it does not.
5. **Selection ranges.** In a line `vlen (x :: xs) = ?rhs`, put the cursor on `xs` and press
   **Expand Selection** repeatedly (Shift+Alt+→; ⌃⇧⌘→ on macOS). The selection grows
   `xs` → `x :: xs` → `(x :: xs)` → the whole clause. In an empty `idris2` editor the command
   selects nothing and logs no error in the Extension Host log.
6. **Editor defaults for `[idris2]`/`[lidr]` in the fresh profile.** In **Preferences: Open
   Settings (UI)**, filtered with `@lang:idris2`, *Semantic Highlighting: Enabled* reads `true`,
   *Tab Size* `2`, *Insert Spaces* on, and *Unicode Highlight: Ambiguous Characters* off. Typing
   `α` or `ℕ` in an `idris2` editor draws no ambiguous-character box.
7. **Document selector.** **Developer: Inspect Context Keys** (the result is in the Developer
   Tools console) shows `idris2.isIdrisDocument` as `true` with an `.idr` or `.lidr` editor
   focused, and `false` with a plain `.md` file focused.
8. **Help commands, no backend needed.**
   - **Idris 2: Show Output** reveals the "Idris 2" output channel.
   - **Idris 2: Open Settings** opens the Settings editor filtered to this extension.
   - **Idris 2: Open Idris 2 Documentation** asks to open `https://idris2.readthedocs.io/en/latest/`
     in the browser.

   Nothing opens a network connection without one of these commands (principle 8).
9. **Snippets.** In an `idris2` file and in an `.ipkg` file, **Insert Snippet** offers the
   snippets from `snippets/idris2.json` and `snippets/ipkg.json`. Expanding one inserts its body,
   and Tab moves through its placeholders.

10. **Restricted Mode.** Open a folder you have not trusted and choose **Don't Trust** (or
    set `security.workspace.trust.emptyWindow` to `false` in the throwaway profile and open a
    single `.idr` file). The file is still highlighted, and the extension appears in
    **Developer: Show Running Extensions**.

Afterwards quit that VS Code instance and run `rm -rf /tmp/vi2-m0` to delete the throwaway
profile.
