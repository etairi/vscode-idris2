# M1 manual checklist

This is the "Manual" test layer of `docs/ARCHITECTURE.md` §12 for milestone M1 (`docs/ROADMAP.md`
§5). Work through it on the packaged extension, with the real `idris2`, before tagging M1. It
checks what the automated suites cannot see: Restricted Mode (the test runner always trusts the
workspace), what the status item, menus, terminals and notifications look like, and the issue
reporter.

**Setup.** As for M0: a throwaway profile under short `/tmp/vi2-*` paths (F17), with
`--shared-data-dir` so that your own trusted-folder list is not used, and `code` standing for
`"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code"` on macOS. Work on a
copy of the fixtures, because step 8 adds a file. Kill only the VS Code processes started this
way, and delete `/tmp/vi2-m1` and `/tmp/vi2-m1-ws` at the end.

```sh
npm run package                                    # → vscode-idris2-<version>.vsix
cp -R test/fixtures/workspaces /tmp/vi2-m1-ws
V=(--user-data-dir /tmp/vi2-m1/u --extensions-dir /tmp/vi2-m1/e --shared-data-dir /tmp/vi2-m1/s --disable-telemetry)
code "${V[@]}" --install-extension vscode-idris2-*.vsix
code "${V[@]}" /tmp/vi2-m1-ws/simple-ipkg
```

1. **Restricted Mode spawns nothing.** When VS Code asks whether to trust the folder, choose
   **Don't Trust** (Restricted Mode). Open `src/Foo/B.idr`.
   - The syntax highlighting works, and the Idris 2 language status item reads
     `Restricted Mode — toolchain detection disabled`.
   - The **Idris 2** output channel says `Toolchain scan 1 (activation, Restricted Mode:
     nothing run)` and `Status: Restricted Mode — toolchain detection disabled`. (Each command
     the extension runs is logged as `Running …` at the Debug level; the process runner refuses
     every request in Restricted Mode, which the unit tests cover.)
   - **Show Setup Information** says that the workspace is not trusted and shows the `idris2`
     it located without having run it.
2. **Granting trust rescans.** Run **Workspaces: Manage Workspace Trust** and trust the folder.
   Within a few seconds the status item reads `Idris 2 <version> · syntax only`, where
   `<version>` is what `idris2 --version` prints after `Idris 2, version ` (0.8.0 on the
   development machine).
3. **Status item and menu agree.** Click the status item: the QuickPick lists the same commands,
   in the same order, as the **Idris 2** submenu in the editor title bar (the tools icon at the
   top right of `B.idr`). The submenu is there for `B.idr` and absent for a Markdown file (open
   `/tmp/vi2-m1-ws/loose-file/Notes.md`).
4. **Setup Information.** Run **Idris 2: Show Setup Information**. The read-only document
   lists: the `idris2` path and how it was found; the raw output of `--version`,
   `--ttc-version`, `--paths` and `--list-packages`; pack as not found; no `idris2-lsp` and no
   verdict; the `simple-ipkg` project with `sourcedir` `src` and `depends` `contrib`, read with
   `--dump-ipkg-json`. Typing in it is refused.
5. **Report Issue…** opens VS Code's issue reporter for this extension with the Setup
   Information text in the body. Close it without submitting.
6. **idris2 missing.** In the user settings set `idris2.toolchain.idris2Path` to
   `/nonexistent/idris2`. One warning appears, with the actions **Install Idris 2…**,
   **Set Path** and **Show Output**; the status item reads `idris2 not found — Setup…`.
   **Idris 2: Rescan Toolchain** does not show the warning a second time in this window.
   **Set Path** opens the setting. Remove the setting again; the status item returns to step
   2's text.
7. **Install commands type and never run.** **Idris 2: Install Idris 2…** opens a terminal
   named "Idris 2: Install Idris 2" with `brew install idris2` typed after the prompt and not
   run (on Linux and Windows it opens Idris 2's INSTALL.md in the browser instead). Its
   working directory is the home directory, not the workspace folder (the default zsh and bash
   prompts show it as `~`).
   **Idris 2: Install pack…** types `bash -c "$(curl -fsSL
   https://raw.githubusercontent.com/stefan-hoeck/idris2-pack/main/install.bash)"`, also not
   run. Close both terminals without pressing Enter. **Idris 2: Install or Update idris2-lsp
   with pack**, with no pack installed, shows a message offering **Install pack…** instead of a
   terminal.
8. **Several `.ipkg` files in one directory (F10).** Copy `simple.ipkg` to `other.ipkg` next to
   it, with `B.idr` still open. The status item turns into a warning whose detail names the
   file the compiler does not read (whichever of the two the directory listing returns second)
   and says that the compiler uses only one; Setup Information lists it too. Delete
   `other.ipkg`; the warning goes away.
9. **Walkthrough.** **Help: Get Started with VS Code** → **Walkthroughs** lists the Idris 2
   walkthrough with three steps (find the toolchain, install, open a project), and each step's
   page renders.
10. **Logs.** The Extension Host log (**Developer: Show Logs…** → Extension Host) has no error
    or warning mentioning `vscode-idris2`. Set the **Idris 2** channel to the Debug level
    (**Developer: Set Log Level…** → Idris 2 → Debug) and run **Idris 2: Rescan Toolchain**:
    the channel shows `Running …/idris2` with `--version`, `--ttc-version`, `--paths` and
    `--list-packages`, the scan summary, then `Running …/idris2 --dump-ipkg-json …/simple.ipkg`
    with the absolute path of the `.ipkg` and `(cwd …)` the directory of `idris2`, not the
    project's (the project is re-read after every scan), and no failure.
