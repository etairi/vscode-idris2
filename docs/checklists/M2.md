# M2 manual checklist

This is the "Manual" test layer of `docs/ARCHITECTURE.md` §12 for milestone M2 (`docs/ROADMAP.md`
§5). Work through it on the packaged extension, with the real `idris2`, before tagging M2. It
checks what the automated suites cannot see: squiggles and hovers as a user sees them, the
consent notification and its buttons (the test runner answers the question from code), a folder
remembered across a window reload, Restricted Mode (the test runner always trusts the workspace),
and what the status item, the output channel and the protocol trace look like.

**Setup.** As for M1: a throwaway profile under short `/tmp/vi2-*` paths (F17), with
`--shared-data-dir` so that your own trusted-folder list is not used, and `code` standing for
`"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code"` on macOS. Work on a
copy of the fixtures, because the steps edit files and the compiler writes `build/` directories.
To see the compiler processes this window starts, and only those, use
`pgrep -fl -- '--ide-mode.*vi2-m2-ws'` (each session is a `sh` wrapper and the compiler behind
it, both with `--ide-mode` in their command line). Kill only the VS Code processes started this
way, and delete `/tmp/vi2-m2` and `/tmp/vi2-m2-ws` at the end.

```sh
npm run package                                    # → vscode-idris2-<version>.vsix
cp -R test/fixtures/workspaces /tmp/vi2-m2-ws
V=(--user-data-dir /tmp/vi2-m2/u --extensions-dir /tmp/vi2-m2/e --shared-data-dir /tmp/vi2-m2/s --disable-telemetry)
code "${V[@]}" --install-extension vscode-idris2-*.vsix
code "${V[@]}" /tmp/vi2-m2-ws/broken
```

1. **Restricted Mode runs nothing and asks nothing.** When VS Code asks whether to trust the
   folder, choose **Don't Trust**. Open `Bad.idr`: highlighting only, no squiggle, no
   notification, and `pgrep` finds no process. Then **Workspaces: Manage Workspace Trust** →
   trust the folder.
2. **A real error squiggle.** With `Bad.idr` open, within a few seconds the language status item
   reads `Idris 2 <version> · IDE mode · 1 error` (after `checking…`). There is one red squiggle,
   under `x + 1` on line 4; its hover starts `While processing right hand side of f`, and the
   Problems panel lists it at line 4, column 7. `pgrep` shows one session.
3. **A warning, and a reload that keeps it (F7).** Open `Warn.idr`: one yellow squiggle under
   `f n` on line 5, `Unreachable clause: f n`, no error; the item reads `1 warning`. Run
   **Idris 2: Check File** on it without changing anything: the compiler rebuilds nothing and
   sends no warning, and the squiggle stays.
4. **Fixing the error.** In `Bad.idr` change line 4 to `f x = show (x + 1)`. Before saving,
   the item reads `stale`, and the protocol trace shows no request for the typing; undo back to the
   saved text before saving: the item reads `1 error` again, still without a request. Make the
   change again; after saving, the squiggle goes and the item reads `✓`. Undo and save
   again: the error is back. Now change the file outside the editor, in a terminal (`sed -i ''
   's/x + 1/show (x + 1)/' Bad.idr` on macOS): VS Code reloads it, the item reads `checking…`
   and then `✓`, and the squiggle goes without a save; the reverse `sed` brings the error back
   the same way. Delete `Bad.idr` in a terminal and copy it back from the repository's fixture:
   it is checked again when it reappears.
5. **A malformed package file (F10).** Open `bad-ipkg/Main.idr`. `bad-ipkg/bad.ipkg` gets one
   diagnostic at line 3, column 1 (`Unrecognised property "pkgs".`), and the item reads
   `package file error`.
6. **Consent outside the workspace folders.** **File → Open File…** →
   `/tmp/vi2-m2-ws/loose-file/Hello.idr` (outside the `broken` folder). A warning notification
   asks `Idris 2: start the compiler in /tmp/vi2-m2-ws/loose-file? …` (or the `/private/tmp/…`
   spelling: the real path) with **Allow**, **Always Allow for This Folder** and **Don't
   Allow**. Until you answer, the file is highlighted only, the item reads `checking…` with the
   detail `waiting for your permission to start the compiler in …` and the link **Allow…**, and
   `pgrep` shows no session for `loose-file`. The question says that it is the folder of the Idris
   file you opened, which belongs to no package. Wait until the notification has gone to the
   notification centre (about 10–15 s), then click the item's **Allow…**: the question is shown
   again, once (not twice in the notification centre). Choose **Don't Allow**: the item reads
   `not allowed here`, with the link
   **Allow…**; **Idris 2: Check File** says why nothing ran, with **Allow…**. Click **Allow…**:
   the question comes again, and while it waits the item reads `checking…` with the link
   **Allow…**; choose **Always Allow for This Folder**: the file is checked (`✓`) and a
   `loose-file` session appears. Then create `/tmp/vi2-m2-ws/[x](command:workbench.action.showCommands)/A.idr`
   (a folder whose name is a link) with `module A` in it and open it: the question and, after
   **Don't Allow**, the item's hover show the folder name as plain text; nothing in either is a
   link (clicking the name opens nothing). Likewise with a folder named `x? It is inside your
   trusted workspace folder.` followed by a line break and a few hundred characters (made with
   `mkdir` in a terminal): the question starts with its own warning and ends with the whole name in
   quotes, the line break written as `\u{A}` and the middle of a long path replaced by `…`. A folder
   named `projˮ — inside the workspace folder ‟/Users/me/work` (U+02EE, U+201F) shows both marks
   written out (`\u{2EE}`, `\u{201F}`). With a folder name of a few hundred characters, the item's
   hover begins with its permission sentence (take a screenshot for the record).
7. **Remembered, then revoked.** **Developer: Reload Window**, then open `loose-file/Hello.idr`
   again: no question, it is checked at once. **Idris 2: Manage Allowed Folders…** lists the
   folder; revoke it: its session stops, the item reads `stopped` with a detail that names the
   revoked folder, and the next check of `Hello.idr` asks again (answer **Don't Allow**).
   **Two windows:** allow `loose-file` for good in window A (checked), open a second window B
   (**File: New Window**, same profile) and revoke it there with **Manage Allowed Folders…**. In A,
   **Stop Backend**, then save `Hello.idr`: A asks again. Answer **Always Allow for This Folder**
   for another folder in A; in B, **Manage Allowed Folders…** lists that folder and not
   `loose-file`.
8. **Stop, restart, crash.** **Idris 2: Stop Backend** (choose all roots if asked): the item
   reads `stopped` and `pgrep` finds nothing. Type in `Bad.idr` without saving: `pgrep` still
   finds nothing. Save `Bad.idr`: a session starts again and the error comes back. **Idris 2: Restart Backend**: `pgrep` shows a new process id. Kill the
   compiler with `kill -9 <pid of the idris2.so process>`: the **Idris 2** output channel
   records the exit, a new session starts by itself, and the next save of `Bad.idr` is checked
   within a couple of seconds.
9. **Transport and settings** (ROADMAP §9 Q20, decided 2026-09-28: stdio by default, the socket
   only as an opt-in in user settings). With no transport setting, `pgrep` shows `--ide-mode`
   (not `--ide-mode-socket`) and `lsof -a -iTCP -sTCP:LISTEN -p <pid of the idris2.so process>`
   lists no listening port. Open `broken/Logging.idr` (it has a `%logging` pragma, so the compiler
   prints `LOG` lines into the stdio stream): it is checked (`✓`), with no crash notice. In the
   user settings set `idris2.ideMode.transport` to `socket`: the running sessions restart
   (`pgrep` shows `--ide-mode-socket`), the visible file is checked again, and checking still
   works; the setting's description says that the compiler serves the first program that
   connects to its port. In the **Workspace** tab of the Settings editor the transport cannot be
   set (its scope is `application`: user settings only; in a remote window, such as a dev
   container, it is not offered in the remote settings either, and a value there is marked as not
   applied), and a `"idris2.ideMode.transport": "socket"` written by hand into
   the folder's `.vscode/settings.json` changes nothing while the user setting is absent (the
   integration suite `loose-stdio` checks this with the fake compiler). Remove the user setting
   again: the sessions restart with `--ide-mode`. Set `idris2.ideMode.extraArgs` to
   `["--ide-mode-socket"]` in the folder's `.vscode/settings.json`: the running processes end and
   none starts again (`pgrep` finds nothing, `lsof -iTCP -sTCP:LISTEN` no port), and the status
   reads `failed`, its detail naming `--ide-mode-socket` in `idris2.ideMode.extraArgs`, also after
   a save. Remove it and save: the file is checked again.
10. **Resource limits** (ROADMAP §9 Q21, decided 2026-09-28: no limits by default). Open one file
    each from `broken`, `loose-file` (allowed in step 7 or allow it now) and `simple-ipkg`
    (**File → Open File…**, allow its folder): three sessions run (`pgrep`). Set
    `idris2.ideMode.maxSessions` to `2` in the user settings: the idle session of the project used
    least recently stops at once (the **Idris 2** output logs `stopped (evicted)`), never the one of
    the file in the active editor, and no other session restarts; its file's diagnostics stay.
    Save that file: its session starts again and another idle one stops. Remove the setting, set
    `idris2.ideMode.maxBackgroundChecks` to `1`, then **Idris 2: Restart Backend → All projects**
    with the three files visible side by side: the processes restart together (the limit is on
    checks, not on starts), the active file is checked at once, the other two one after the other
    (`checking…` while they wait); make a waiting one the active editor: it is checked at once.
    Open three files of one project side by side and save each of the two that are not active,
    then the active one, while the first save's compile runs (a project whose first load takes a
    few seconds): the active file's check finishes before the second background one starts
    (**Idris 2** output with the protocol trace on: its `:load-file` is sent right after the one
    being compiled). Open a second window on another folder: its sessions do not count against
    this window's limits (each window counts its own; the settings say so).
    Run **Restart Backend → All projects** again and, while a file still waits, **Stop Backend →
    All projects**: `pgrep` finds nothing, and the waiting file keeps what it showed. With the
    **Idris 2** output panel focused, check that the status item still describes the Idris file
    that was active before. Remove the setting.
11. **Protocol trace.** Set `idris2.trace.protocol` to `true` and run **Idris 2: Show Protocol
    Trace**; save `Bad.idr`: the channel shows the `:load-file` request with its six-digit
    prefix and the replies, including the `:warning`. **Idris 2 (Developer): Send Raw Protocol
    Request…** (only in the palette while the trace is on) with `:version` → the trace shows
    `(:version N)` and `(:return (:ok ((0 8 0) (""))) N)` (for 0.8.0). Set the setting back to
    `false`; the developer command leaves the palette. In the **Workspace** tab of the Settings
    editor `idris2.trace.protocol` cannot be set (its scope is `application`, user settings only).
