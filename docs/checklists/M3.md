# M3 manual checklist

This is the "Manual" test layer of `docs/ARCHITECTURE.md` §12 for milestone M3 (`docs/ROADMAP.md`
§5). Work through it on the packaged extension, with the real `idris2`, before tagging M3. It
checks what the automated suites cannot see: how hovers, inlay hints, semantic colours and the
inline evaluation result look, that compiler text is shown as text and never as links or markup,
keyboard shortcuts pressed on a real keyboard (no API dispatches a key; the integration suite
reads VS Code's resolved bindings instead), and when the `eval` session's process appears and
goes.

**Setup.** As for M2: a throwaway profile under short `/tmp/vi2-*` paths (F17), with
`--shared-data-dir`, and `code` standing for
`"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code"` on macOS. Work on a copy
of the fixtures. `pgrep -fl -- '--ide-mode.*vi2-m3-ws'` lists this window's compiler processes (a
`sh` wrapper and the compiler behind it per session); the `eval` session's command line names
`build/.vscode-idris2-eval`. Kill only the VS Code processes started this way, and delete
`/tmp/vi2-m3` and `/tmp/vi2-m3-ws` at the end.

```sh
npm run package                                    # → vscode-idris2-<version>.vsix
cp -R test/fixtures/workspaces /tmp/vi2-m3-ws
V=(--user-data-dir /tmp/vi2-m3/u --extensions-dir /tmp/vi2-m3/e --shared-data-dir /tmp/vi2-m3/s --disable-telemetry)
code "${V[@]}" --install-extension vscode-idris2-*.vsix
code "${V[@]}" /tmp/vi2-m3-ws/simple-ipkg
```

1. **Hover, definition, documentation.** Open `src/Foo/B.idr` and trust the folder. Hover over
   `greeting` on line 7: the type `Foo.B.greeting : String` in an Idris code block and nothing
   else (`greeting` has no docstring, so there is no overview). **F12** on `shout` opens
   `src/Foo/A.idr` with lines 3–4 (`export` to the end of the signature) selected. Open
   `src/Foo/Shapes.idr` and hover over `area`: its type, and the overview `The area of a shape.`
   in a plain code block under it. With the cursor on `area`, **Idris 2: Type at Cursor** shows that hover at the cursor;
   **Idris 2: Docs at Cursor** opens a read-only document beside the editor, in the Plain Text
   language mode (the status bar says so), containing
   `The area of a shape.`; **Idris 2: Show Documentation…** asks for a name with `area` suggested,
   and Enter opens the same document. **F12** on `pi` (line 13) opens the installed prelude source
   (`…/prelude-0.8.0/Prelude/Types.idr` under the Homebrew cellar for 0.8.0) at `pi`'s declaration.
   Hover over `r` in `area (Circle r) = pi * r * r`: `r : Double`. **Idris 2: Browse
   Namespace…** with `Foo.Shapes` lists its nine names with their types, `(|+|)` last.
2. **Compiler text is text.** Add to `Shapes.idr`, above `scale`, a doc comment with markup in
   it, and save:

   ```idris
   ||| [run](command:workbench.action.showCommands) <b>bold</b> $(zap) *em*
   |||   ```
   ||| # heading after an indented fence
   ```

   Hover over `scale`, open **Show Documentation…** and **Browse Namespace…** `Foo.Shapes`: the
   link text, the tag, `$(zap)`, the asterisks, the backticks and `#` appear literally — no link
   (clicking the text opens nothing), no bold, no icon, no heading, and the hover's code block
   still holds only the type. Undo the change and save.
3. **Semantic colours and the `.lidr` offset.** In `Shapes.idr`, with a colour theme that
   colours semantic tokens (e.g. Dark Modern), constructors (`Circle`, `Rectangle`) are coloured
   differently from functions (`area`, `scale`), and bound variables (`r`, `w`, `h`) differently
   again; **Developer: Inspect Editor Tokens and Scopes** on `Circle` shows the semantic token type
   `enumMember`, on `area` `function`. **File → Open File…** `/tmp/vi2-m3-ws/loose-file/Lit.lidr`
   (allow its folder): `module` on line 1 is coloured from column 3 (after `> `), and the prose
   line is not coloured as code.
4. **Inlay hints.** **File → Open File…** `/tmp/vi2-m3-ws/broken/Clean.idr` (allow its folder):
   after `xs` on line 8 the hint `: Vect ?_ ?_` appears. Type a character at the end of line 8
   without saving: the hints stay where they are, and no text moves; add an empty line above line
   7: the hints of lines 7 and 8 move down with them; undo both: they are where they were. Set
   `idris2.inlayHints.variableTypes` to `false`: they go;
   remove the setting. With `editor.inlayHints.enabled` set to `offUnlessPressed` they show only
   while Ctrl+Alt (macOS: Ctrl+Option) is held.
5. **Completion.** In `Clean.idr`, on a new line type `vl` and press Ctrl+Space: `vlen` and
   `vlen_rhs` are offered, each once. Typing is never blocked, also right after a save (the first
   completion after a load takes up to a second in the compiler, docs/measurements/first-load.md);
   delete the line and save.
6. **Evaluation.** In `Clean.idr` add the comment lines `-- the (Vect 2 Nat) [1,2]`,
   `-- the (IO ()) (putStrLn "hi")`, `-- putStrLn "hi"` and `-- :exec putStrLn "hi"` (unsaved is
   fine). Select each expression after `-- ` and run **Idris 2: Evaluate Selection**:
   - the first shows `[1, 2]` after the end of its line, and in a hover over the selected text;
     `pgrep` now shows a second process for `broken`, with `.vscode-idris2-eval` in its command
     line (it starts only at the first evaluation);
   - the second shows `MkIO (prim__putStr "hi\n")`, and nothing is printed anywhere (the **Idris
     2** output channel shows no `hi`);
   - the third shows the compiler's error `Can't find an implementation for HasIO ?io.` as the
     result, not as a notification of failure;
   - the fourth is refused with a notification that says Evaluate evaluates expressions only (no
     link in it), and the protocol trace (`idris2.trace.protocol` on) shows no request for it.
   **Idris 2: Clear Evaluation Results** removes the inline results. Set
   `idris2.eval.inlineResults` to `false` and evaluate the first again: the result comes as a
   notification instead. After **Stop Backend** `pgrep` finds neither process; the next
   evaluation starts only the `eval` session again. A selection over three lines of a `let` block
   (`r = let a = 1` with `b = 2` under `a`, `in a + b`, selected from `let`) shows `3`. Then set
   `idris2.eval.timeout` to `3000`, add `loop : Nat -> Nat` / `loop n = loop (S n)`, save, and
   evaluate `loop 0`: after about a second a notification offers **Cancel**, which ends the
   evaluation (no failure notification) and the `eval` process (`pgrep`); evaluate it again and
   wait: after 3 s a warning says the evaluation did not finish within 3 s, and `pgrep` finds no
   `eval` process until the next evaluation. Revert the file and the setting.
7. **Keyboard shortcuts** (ROADMAP §9 Q5). With the default `idris2.keybindings.scheme` (`auto`):
   on macOS **Control+C Control+T** in an Idris editor runs Type at Cursor, **Control+C
   Control+D** Docs at Cursor, **Control+C Control+E** Evaluate Selection, and Cmd+C still
   copies; on Linux the same with **Ctrl+Alt+I T / D / E**. Set the scheme to `prefix` (on macOS)
   or `chords` (on Linux) in the user settings: the other form works and the first does nothing.
   On Linux under `chords`, Ctrl+C no longer copies in Idris editors and still copies in other
   editors, as the setting's description says. Under `none` no shortcut runs the commands, which
   stay in the Command Palette. The Settings editor's **Workspace** tab does not offer the
   setting. In a Markdown file (`loose-file/Notes.md`) none of the shortcuts does anything of
   this extension.
8. **Restricted Mode.** Open `/tmp/vi2-m3-ws/broken` in a new window and choose **Don't Trust**:
   hovers show no compiler type, no inlay hints, no semantic colours beyond the grammar's;
   Evaluate Selection, Type/Docs at Cursor, Show Documentation… and Browse Namespace… are not in
   the Command Palette; `pgrep` finds nothing.
